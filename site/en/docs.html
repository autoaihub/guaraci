The complete guide to Guaraci

From installation to the detail of every field: everything you need to collect official public data, through the web interface or the command line. No rush, no hidden jargon, with each of the 259 datasets documented one by one.

Overview

Guaraci is a public data download orchestrator: it connects directly to the official sources (DATASUS via the microdata FTP, the Ministry of Health's open catalog, IBGE through the SIDRA API, NASA and gov.br, among others) and delivers the data ready to use as CSV, Parquet or SQLite.

Three principles guide the project:

  • Primary source, always. Guaraci never fetches from mirrors or third-party curation: each dataset comes from the official system that produces it. You receive the data as up to date as the source has published it, traceable to its origin.
  • Fidelity to the original data. The collection preserves the published content, and converting technical formats (such as DATASUS's .dbc) does not change the values.
  • Docker first. The officially supported path runs in a Docker container, so the environment is identical on any machine, with no dependency conflicts.

There are two entry points, with the same engine: the web interface (forms in the browser, no code) and the command line guaraci fetch (for automation and scripts). Both read the same parameter schema documented in the catalog.

1 · Installation

You need two free programs: Git (copies the project) and Docker Desktop (runs Guaraci). Install both with the default options and leave Docker Desktop open.

1.1 Copy the project

Open the terminal (on Windows, look for PowerShell in the Start menu) and type:

PowerShell
> git clone https://github.com/autoaihub/guaraci.git
> cd guaraci

1.2 Check Docker before continuing

The most common cause of installation failure is Docker Desktop not being ready (closed, still starting, or with an unresponsive engine), not a problem with Guaraci. Run the diagnostic below first whenever something gets stuck:

PowerShell: guaraci
> .\scripts\desktop\check-docker.cmd
[OK] Docker CLI
[OK] Docker Desktop (engine)
✔ Docker is ready.

On Linux or macOS: ./scripts/desktop/check-docker.sh. The script says exactly what is failing and how to fix it. If it passes ([OK] everywhere) and Guaraci still fails, the problem is with Guaraci, not Docker.

1.3 Build the image (only once)

PowerShell: guaraci
> docker build -t guaraci .
[+] Building... ok
Rebuild only when dependencies are updated. If you suspect a broken cache, use docker build --no-cache -t guaraci ..

1.4 Start Guaraci

Recommended way (Windows). The launcher starts the container, waits for the health check and opens the interface by itself:

PowerShell: guaraci
> .\scripts\desktop\start-guaraci.cmd
✔ Guaraci is up: http://localhost:8002/

On Linux or macOS: ./scripts/desktop/start-guaraci.sh. To check the status, status-guaraci; to shut down, stop-guaraci.

Manual way (useful for debugging: the terminal keeps showing the logs and Ctrl+C stops it):

PowerShell: guaraci
> docker run --rm -it -p 8002:8000 -v "${PWD}:/app" guaraci uvicorn guaraci.api.main:app --host 0.0.0.0 --port 8000 --no-access-log
Always mount the volume (-v "${PWD}:/app"). Without it, downloads and manifests are lost when the container stops.

1.5 Check that everything works

PowerShell
> Invoke-RestMethod http://localhost:8002/health
{"status": "ok", "version": "0.6.0"}

2 · Web interface

With Guaraci running, the interface is at http://localhost:8002. The whole flow happens on one screen:

  1. Choose the source. The list has the 271 catalog entries (259 distinct datasets, plus the alternative routes to the same dataset) with search. Each one exposes its own parameters, and the form builds itself from the schema (the same one documented in the catalog).
  2. Fill in the basic filters. Period (years), states, groups or diseases, depending on the source. The advanced fields (pagination, alternative URL, raw snapshot) stay collapsed, and the defaults suit most cases.
  3. Choose the export format. CSV (opens in Excel), Parquet (data analysis) or SQLite (local database). With no format, Guaraci only collects and records the manifest.
  4. Create the download and follow it. The progress bar and live log show each file being fetched, validated and converted. Jobs stay in the history, so you can repeat or debug them later.
  5. Open the result. The files go to the Guaraci Downloads folder (on the Desktop, by default), together with a manifest.json describing the collection.
For large DATASUS sources (SIA, SIH, CNES), use the discovery preflight before downloading: it counts the files by group and state without transferring anything, in the interface or with guaraci fetch discover.

3 · Command line

The guaraci fetch group reaches any registered source with four subcommands. Inside Docker, prefix it with docker run --rm -v "${PWD}:/app" guaraci (or use the interactive shell).

3.1 fetch list: what exists

terminal
> guaraci fetch list
sih · sim · sinan · sinasc · dengue · nasa_power · ibge_populacao ... 271

3.2 fetch schema: a source's parameters

terminal
> guaraci fetch schema dengue
nu_ano (string) · output_format [csv|parquet|sqlite] · batch_size (int, 1000) ...

3.3 fetch discover: measure before downloading

Available for SIH and the eleven DATASUS FTP microdata systems (SIA, CNES, SINASC and so on): it counts files by group and state without downloading anything. With --sizes, it also adds up the total size. SIM and SINAN resolve their files internally during collection and are left out of the preflight.

terminal
> guaraci fetch discover sih --set start_year=2024 --set end_year=2024 --set states=SP --sizes
RD · SP · 12 files · 198.4 MB

3.4 fetch run: collect

terminal
> guaraci fetch run sinan --set disease=DENG --set start_year=2023 --set end_year=2024 --format csv
DENGBR23.dbc → csv → sinan_deng_2023-2024.csv

Useful rules:

  • --set KEY=VALUE is automatically converted to the type declared in the schema (integer, boolean, list).
  • Omit --format to collect without exporting (only the manifest is written).
  • -o FOLDER changes the destination (default: Guaraci Downloads on the Desktop).
  • NASA credentials are never flags, only environment variables (section 5).

Each source in the catalog comes with a fetch run example ready to copy.

4 · Formats and output

FormatWhen to use
csvOpen in Excel or LibreOffice and share with people who do not code.
parquetData analysis (pandas, polars, R, Spark): compact and fast, preserves types.
sqliteLocal SQL queries with no server, in a single .db file.
  • manifest.json: every collection writes a manifest with source, parameters, files and timestamps, which is the data's provenance record.
  • keep_raw=true: besides the export, saves the raw snapshot (raw/*.jsonl for APIs) for auditing.
  • export_warning: if the filters zero out the records or pagination truncates (max_pages), the notice appears in the manifest and the logs. It is the first place to look when “nothing came back”.
  • Source formats: DATASUS .dbc and .DBF files are decoded automatically, and you never need to deal with them.

5 · Credentials (NASA)

Almost everything in Guaraci needs no sign-up. The exceptions are two NASA sources, and the keys are free:

SourceCredentialEnvironment variableWhere to get it
nasa_firmsMAP_KEYGUARACI_FIRMS_MAP_KEYfirms.modaps.eosdis.nasa.gov
nasa_gpmEarthdataGUARACI_EARTHDATA_TOKENurs.earthdata.nasa.gov (authorize the NASA GESDISC DATA ARCHIVE app)

nasa_power and all IBGE, OpenDataSUS, DATASUS and gov.br sources require no credential. For safety, keys are read only from the environment: they never become a job parameter and are never written to a manifest.

PowerShell
> $env:GUARACI_FIRMS_MAP_KEY = "your-key-here"
(Linux/macOS: export GUARACI_FIRMS_MAP_KEY=your-key-here)

6 · Orchestrator (server use)

For those who maintain a continuous archive (such as the Sabiá data lake), guaraci orchestrate automates collection in two bronze layers:

  • raw/: the raw official file, at the source's native granularity (annual SINAN stays annual; monthly SIH stays monthly).
  • refined/: the same rows repartitioned into the uniform tree source/group/state/year/month, sliced by event date.

Commands: orchestrate profiles (cadence of each source), plan (dry run), backfill (full history), update (only the delta, driven by a CSV ledger) and status. The scripts/server/orchestrate.{sh,ps1} wrappers, ready for cron, handle locking and logging. Details are in docs/ORCHESTRATOR.md in the repository.

7 · Best practices

  • Start small. Use the shortest time window and the narrowest filters possible, and widen them once the flow is validated.
  • Measure before downloading. For large FTP sources (SIA, SIH, CNES), run fetch discover first, because broad selections can resolve to thousands of files and many gigabytes.
  • Export only when you need to. Set output_format only when you want the final dataset; collection without export is faster and is already recorded.
  • Watch the export_warning. It flags empty exports and truncated pagination.
  • Current-year data is partial. DATASUS sources accept the current year, but publication lags by about 2 to 3 months, so compare with care.
  • Cite the official source. The terms of use are those of the producing institution; Guaraci ships a CITATION.cff in case you also want to cite the tool.
